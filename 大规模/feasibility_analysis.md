# 大规模模拟可行性分析（280 温度点方案）

> 日期：2026-03-24
> 作者：刘宗岳
> 基于 N=128/256/512/1024 已有数据的定量分析
>
> **现有脚本参数**：126 点（5 低温 + 80 峰值 + 26 中温 + 15 高温），MAX_PARALLEL=30，cpus-per-task=32
> **新方案目标**：280 点（加密一倍），每个温度点的 nmeas 保持不变

## 2. N=1024 数据问题诊断

N=1024 的 γ_MC = 1.9497 偏高于真实值，而 N=512 的 1.9406 更接近。这不符合单调收敛的预期。原因分析：

### 2.1 低温区异常

| T     | N=512 Cv/N | N=1024 Cv/N | 倍数   | N=512 相对误差 | N=1024 相对误差 |
|-------|-----------|------------|--------|--------------|---------------|
| 0.050 | 0.0054    | 0.1257     | **23x** | 77%          | 23%           |
| 0.062 | 0.0223    | 0.0687     | 3x     | 30%          | 11%           |
| 0.075 | 0.1485    | 0.0773     | 0.5x   | 9.2%         | 8.8%          |

T = 0.050 处 N=1024 的 Cv/N 是 N=512 的 23 倍，这在物理上不合理（大 N 的低温 Cv 应该更小或相当）。
最可能的原因：**N=1024 在低温未充分平衡**。τ_int ~ 48000，nmeas = 10^8 只给出约 2000 个独立样本，而系统可能需要更长的热化时间才能找到真正的基态构型。

### 2.2 积分精度

N=512 与 N=1024 的积分分别为 2.9318 和 2.9449。差值 0.013 中，低温区的贡献虽然绝对值小，但 N=1024 的低温异常使得积分偏大，导致 s_0 偏小、γ 偏大。

### 2.3 温度网格偏粗

当前 N=512 和 N=1024 均只有 126 个点，峰值区步长 0.005。而 N=128 有 318 个点（峰值区步长 0.001），积分精度更高。N=512/1024 的网格密度不足可能导致梯形积分的系统偏差。

## 3. 280 点温度网格设计

将原 126 点方案加密至 280 点。核心思路：**峰值区加密到步长 0.0025，中温区显著加密，低温和高温区适度补充**。

### 现有脚本 vs 新方案对比

| 区域   | 旧方案点数 | 旧 nmeas | 新方案点数 | 新步长       | **新 nmeas（统一）** |
|--------|----------|---------|----------|------------|-------------------|
| 低温区  | 5        | 10^7    | 11       | 0.005      | **10^8**          |
| 峰值区  | 80       | 10^8    | 160      | 0.0025     | **10^8**          |
| 中温区  | 26       | 10^7    | 70       | 0.025~0.1  | **10^8**          |
| 高温区  | 15       | 10^6    | 39       | 不等间距     | **10^8**          |
| **总计**| **126**  |         | **280**  |            | **全部 10^8**      |

**关键变化：所有 280 个温度点统一 nmeas = 10^8，therm = 2 × 10^6。不再分区域设置不同的步数。**

### 区域 1：低温区（T = 0.050 ~ 0.100，11 个点）

```
旧：T = 0.0500, 0.0625, 0.0750, 0.0875, 0.1000  （5点，不等间距）
新：T = 0.050, 0.055, 0.060, 0.065, 0.070, 0.075, 0.080, 0.085, 0.090, 0.095, 0.100
    （11点，步长 0.005）
```

- **nmeas = 10^8**（旧值 10^7，提升 10 倍），therm = 2 × 10^6（旧值 10^6，加倍）
- 加密原因：诊断低温区平衡性，特别是 N=1024 在 T=0.05 处的 Cv/N 异常
- nmeas 提升 10 倍 + therm 翻倍，显著改善低温平衡性和统计量

### 区域 2：峰值区（T = 0.1025 ~ 0.500，160 个点）— 关键区域

```
旧：T = 0.1050, 0.1100, ..., 0.5000  （80点，步长 0.005）
新：T = 0.1025, 0.1050, 0.1075, ..., 0.5000  （160点，步长 0.0025）
```

- **nmeas = 10^8**，therm = 2 × 10^6（与旧峰值区相同）
- 步长减半可将梯形积分系统误差降低至原来的 1/4
- 特别是在 Cv/N 变化最剧烈的 T = 0.10 ~ 0.20 区间（Cv/N 从 0.53 上升到 1.56），更密的网格至关重要

### 区域 3：中温区（T = 0.525 ~ 5.0，70 个点）

```
旧：0.55, 0.60, ..., 2.00, 2.50, ..., 5.00  （26点，步长 0.05~0.5）
新：
  T = 0.525, 0.550, 0.575, 0.600, 0.625, 0.650, 0.675, 0.700,
      0.725, 0.750, 0.775, 0.800, 0.825, 0.850, 0.875, 0.900,
      0.925, 0.950, 0.975, 1.000                                    （20点，步长 0.025）
  T = 1.05, 1.10, 1.15, 1.20, 1.25, 1.30, 1.35, 1.40,
      1.45, 1.50, 1.55, 1.60, 1.65, 1.70, 1.75, 1.80,
      1.85, 1.90, 1.95, 2.00                                        （20点，步长 0.05）
  T = 2.10, 2.20, 2.30, 2.40, 2.50, 2.60, 2.70, 2.80, 2.90, 3.00  （10点，步长 0.10）
  T = 3.10, 3.20, 3.30, 3.40, 3.50, 3.60, 3.70, 3.80, 3.90, 4.00,
      4.10, 4.20, 4.30, 4.40, 4.50, 4.60, 4.70, 4.80, 4.90, 5.00  （20点，步长 0.10）
  共 70 个点
```

- **nmeas = 10^8**（旧值 10^7，提升 10 倍），therm = 2 × 10^6
- 此区域 τ_int ≤ 7，10^8 步给出 > 10^7 个独立样本，远超需要
- 旧方案在 T > 2 区域步长为 0.5，过粗；新方案统一加密到 0.1

### 区域 4：高温区（T = 5.5 ~ 500，39 个点）


- **nmeas = 10^8**（旧值 10^6，提升 100 倍），therm = 2 × 10^6
- 加密 T = 5~20 区间有助于更精确拟合 1/T^2 尾部

### 总点数：11 + 160 + 70 + 39 = 280 个点

## 4. 统计量充足性分析

### 4.1 峰值区（核心区域）

nmeas = 10^8，步长 0.0025。

| T     | τ_int | 独立样本数 | Cv/N 相对误差 | 判定 |
|-------|-------|-----------|-------------|------|
| 0.105 | 25,305| 3,952     | ~1.4%       | 可接受（Cv/N 变化快，密网格补偿） |
| 0.120 | 9,063 | 11,034    | ~0.5%       | 充足 |
| 0.150 | 1,582 | 63,199    | ~0.6%       | 充足 |
| 0.200 | 252   | 397,000   | ~0.16%      | 充足 |
| 0.225 | 130   | 769,000   | ~0.15%      | 充足 |
| 0.250 | 77    | 1,299,000 | ~0.12%      | 充足 |
| 0.300 | 33    | 3,030,000 | ~0.08%      | 充足 |
| 0.400 | 12    | 8,333,000 | ~0.05%      | 充足 |
| 0.500 | 7     | 14,286,000| ~0.03%      | 充足 |

**结论**：峰值区（贡献积分 70%）的所有温度点，10^8 步的统计量充足。关键的 T = 0.15 ~ 0.50 区间相对误差 < 0.6%。

### 4.2 低温区的注意事项

T < 0.1 区域 τ_int 极大（30000 ~ 48000），10^7 步只有 200 ~ 330 个独立样本。但这不影响最终结果：

- Cv/N 在 T < 0.1 对积分的贡献 < 3%（见已有 N=128 数据）
- 即使 Cv/N 有 10% 的误差，对总积分的影响 < 0.3%
- 低温区的作用主要是**验证基态冻结**和**诊断平衡性**

**建议**：对 N=1024，如果低温区（T < 0.075）的 Cv/N 仍然异常偏大，应额外增加热化步数到 5 × 10^6 或 10^7，单独重跑这几个点。

### 4.3 中温区和高温区

| 区域   | nmeas | τ_int | 独立样本数  | 相对误差 |
|--------|-------|-------|-----------|---------|
| 中温区  | 10^7  | 5~7   | 1.4M~2M   | < 0.1%  |
| 高温区  | 10^6  | 5     | 200,000   | < 0.3%  |

**结论**：完全足够。

### 4.4 积分精度提升估算

梯形法则误差正比于 h^2（h 为步长）。峰值区步长从 0.005 减半到 0.0025，积分系统误差降为原来的 1/4。

当前 N=512 积分 = 2.9318，γ = 1.9406。假设梯形误差约为 0.001 量级，加密后可降至 < 0.0003，对 γ 的修正约 0.0003，使 γ 更接近 1.941 或 1.940。

## 5. 计算成本（新方案：280 核同时跑，每核负责一个温度的全部 8 个尺度）

### 5.1 新方案核心思路

- **280 个温度点 × 1 核/点 = 280 核并行**
- 每个核心串行跑同一温度的 N = 8, 16, 32, 64, 128, 256, 512, 1024 共 8 个尺度
- **所有温度点统一使用 nmeas = 10^8，therm = 2 × 10^6**（按 max 对齐）
- 好处：所有核心工作量完全相同，同时完成，无需区分低温/峰值/高温的不同 nmeas

### 5.2 各尺度单点耗时（nmeas = 10^8 + therm = 2 × 10^6，单核）

基于已有 benchmark（N=128: 3.4s/M, N=256: 6.7s/M, N=512: 15.6s/M），每次翻倍约 2.3x：

| N    | 秒/10^6 步 | nmeas=10^8 耗时 | +热化 总耗时 |
|------|-----------|---------------|------------|
| 8    | 0.23      | 23 秒          | 23 秒      |
| 16   | 0.44      | 44 秒          | 45 秒      |
| 32   | 0.88      | 1.5 分钟       | 1.5 分钟   |
| 64   | 1.73      | 2.9 分钟       | 2.9 分钟   |
| 128  | 3.40      | 5.7 分钟       | 5.8 分钟   |
| 256  | 6.70      | 11.2 分钟      | 11.4 分钟  |
| 512  | 15.60     | 26.0 分钟      | 26.5 分钟  |
| 1024 | 36.32     | 60.5 分钟      | 61.7 分钟  |

### 5.3 每个核心的总耗时

每个核心串行跑 8 个尺度：

```
总耗时 = 23s + 45s + 90s + 174s + 348s + 684s + 1590s + 3702s
       = 6656 秒 ≈ 111 分钟 ≈ 1.85 小时
```

**其中 N=1024 占 56%，N=512 占 24%，N≤256 合计仅 20%。**

### 5.4 总计算资源

| 项目              | 数值         |
|-------------------|-------------|
| 并行核心数         | 280         |
| 每核墙钟时间       | ~1.85 小时   |
| 总 CPU 时间       | 280 × 1.85 = **518 CPU·小时** |
| 实际墙钟时间       | **≈ 2 小时** |
| 所需核心 / 可用核心 | 280 / 878 = **32%** |

### 5.5 与旧方案对比

| 方案             | 温度点 | 尺度数 | 并行核心 | 墙钟时间    |
|------------------|-------|--------|---------|-----------|
| 旧（只跑 N=512） | 126   | 1      | 30      | ~2.4 小时  |
| 旧（N=512+1024） | 126   | 2      | 60      | ~5 小时    |
| **新方案**       | **280** | **8** | **280** | **~2 小时** |

新方案一次性跑完全部 8 个尺度 × 280 个温度点 = **2240 次模拟**，
墙钟时间反而更短，因为充分利用了服务器的并行能力。

### 5.6 统一 nmeas 的额外收益

旧方案中低温区只用 10^7、高温区只用 10^6，现在统一到 10^8：

| 区域   | 旧 nmeas | 新 nmeas | 改善 |
|--------|---------|---------|------|
| 低温区  | 10^7    | 10^8    | 独立样本增加 10 倍，低温平衡性诊断更可靠 |
| 中温区  | 10^7    | 10^8    | 独立样本增加 10 倍，虽然本来就够 |
| 峰值区  | 10^8    | 10^8    | 不变 |
| 高温区  | 10^6    | 10^8    | 独立样本增加 100 倍，高温尾部更精确 |

低温区的改善最有意义：N=1024 在 T=0.05 处 τ_int ~ 48000，旧方案 10^7 步只有 ~200 个独立样本；新方案 10^8 步有 ~2000 个，误差降低 √10 ≈ 3 倍。

## 6. 可行性结论

### 6.1 N=512（推荐优先执行）

| 维度      | 评估                                           |
|-----------|-----------------------------------------------|
| 物理意义   | γ_MC 已收敛到 1.9406（偏差 0.07%），加密网格可进一步提升积分精度 |
| 统计量     | 10^8 步在峰值区给出 > 60 万独立样本，相对误差 < 0.6%，**充足** |
| 计算成本   | 60 核仅需 1.2 小时，**完全可行**                    |
| 风险       | 无。低温区虽然样本少，但对积分影响可忽略              |

### 6.2 N=1024（建议同步执行，但需注意低温区）

| 维度      | 评估                                           |
|-----------|-----------------------------------------------|
| 物理意义   | 当前 γ_MC = 1.9497 偏高，需要更密网格修正积分误差       |
| 统计量     | 峰值区与 N=512 相同（τ_int 不随 N 增长），**充足**     |
| 计算成本   | 60 核约 5 小时，**可行**                           |
| 风险       | **低温区（T < 0.075）可能未平衡**。建议对 T ≤ 0.075 的点增加热化到 5 × 10^6 步 |

### 6.3 总体判断

**完全可行。** 280 点方案相比当前 126 点：
1. 峰值区步长减半（0.005 → 0.0025），梯形积分误差降为 1/4
2. 低温区和中温区加密，有利于诊断数据质量
3. 计算量翻倍但绝对值仍然很小（N=512 仅 1.2 小时 @60核）
4. 统计量（nmeas）保持不变，每个点的精度与现有数据相同，**已被证明足够**

## 7. 执行方案：SLURM Array Job

### 7.1 架构

```
sbatch --array=0-279 run_all_sizes.sh
```

- 每个 array task 分配 1 个 CPU 核心
- 每个 task 根据自己的 `$SLURM_ARRAY_TASK_ID` 读取对应温度
- 在该温度下串行运行 N = 8, 16, 32, 64, 128, 256, 512, 1024
- 统一参数：nmeas = 10^8，therm = 2 × 10^6，nbin = 200
- 输出：每个尺度一个文件，最后合并为 `data_N{size}.dat`

### 7.2 输出结构

```
大规模/results/
  T0.0500/  result_N8.dat  result_N16.dat ... result_N1024.dat
  T0.0550/  ...
  ...
大规模/data_N8.dat      ← 合并后的 280 个温度点
大规模/data_N16.dat
...
大规模/data_N1024.dat
```

### 7.3 不复用旧数据

由于所有温度点统一升级到 nmeas = 10^8（旧方案低温/中温/高温分别为 10^7/10^7/10^6），且 therm 统一升级到 2 × 10^6，**建议全部重跑**，确保数据自洽。

旧数据（figures/ 中的 data_N512.dat 等）保留作为对比验证。
